# 安全审查技能（security-audit）

给代码做「安全检查」：查敏感信息泄露 → 查 SQL 注入 → 查配置文件 → 查其他隐患 → 交中文报告。

只做检查和报告，不擅自修改代码；修复方案要交给用户拍板。

## 步骤

### 1. 确定审查范围
- 用户指定了文件/目录 → 查它
- 未指定 → 优先查当前未提交的改动（`git status` + `git diff`），其次查全项目
- 范围过宽时按功能模块分次查（如：数据库层、界面层、配置）

### 2. 查敏感信息泄露（密码、密钥写死在代码里）
用 Grep 搜索常见危险词（大小写不敏感）：`password`、`passwd`、`pwd`、`token`、`secret`、`api_key`、`apikey`、`private key`、`BEGIN RSA`、密码、密钥、口令
- 判断真假：测试文件里的假数据、注释里的示例值不算泄露；真实凭据才算，按严重程度报告
- 顺带用 `git log -S "<关键词>"` 查敏感信息是否进过 git 历史（历史里的泄露也要报告）

### 3. 查 SQL 注入风险
本项目 SQL 全部集中在 `src/main/db.ts`，用 node:sqlite：
- 安全写法：`db.prepare(...)` + `?` 占位符传值（参数化），值里的任何字符都只是「数据」不是「命令」
- 危险写法：把用户输入用字符串拼接进 SQL（`+`、`${}`、`concat`），尤其是拼表名、列名、ORDER BY、LIKE 模式
- 检查 IPC 接口收到的值（金额、日期、分类名、备注）是否未经校验就直接进 SQL
- 注意：`WHERE date LIKE ?` 配 `%` 通配符是参数化查询，不是注入；但若通配符逻辑导致返回范围与预期不符（如 `%` 被当普通字符查不到），可提为低风险备注

### 4. 查配置文件明文敏感信息
检查这些位置：`.env`、`.env.*`、`*.config.*`、`package.json`、`electron-builder.yml`、`build/` 目录、`src/**/env.d.ts`
- 有没有真实密码、真实密钥、真实 token 明文存放
- 示例值（`xxx`、`your-key-here`、占位符）不算泄露，但可提醒
- 检查 `.gitignore` 是否漏排除敏感文件（如 `.env` 没进 .gitignore 会被 git 存档）

### 5. 查其他常见隐患（按本项目情况定制）
- **IPC 输入校验**：`src/main/index.ts` 里各接口收到的参数是否校验（金额必须正数、日期格式、类型白名单）。没有校验的接口，检查数据库约束能否兜底
- **XSS 风险**：搜索 `v-html`、`innerHTML`、`eval`、`new Function`。用户输入的备注、分类名如果被当 HTML 渲染，就是风险
- **Electron 窗口安全**：`webPreferences` 里 `nodeIntegration` 应为 false（默认）、`contextIsolation` 应为 true。本项目 `sandbox: false` 是踩坑记录里的已知配置，若它没被改回去要确认 contextIsolation 仍然开启
- **外部链接**：`shell.openExternal` 的地址是否校验协议（只放行 http/https），防止恶意链接打开本地程序
- **路径穿越**：凡是用用户输入拼接文件路径的地方，查 `../` 是否能逃出预期目录
- **依赖漏洞**：可选，执行 `npm audit`（需联网；国内网络失败时如实说明，不阻塞报告）
- 审查时可参考环境里的内置 security-review 技能（若有）作为检查清单补充

### 6. 生成中文安全审查报告
用以下格式向用户汇报（这是给用户的报告，不是开发者的原始输出）：

```
🔒 安全审查报告

📋 审查范围：<文件/目录/未提交改动>
✅ 通过：N 项
⚠️ 问题：N 项（按严重程度排列）

<逐条列出查了什么，一句话一条，用大白话>
- 「……检查……」✅ 安全

<如有问题：>
🔴 高风险：
- 文件:行号 — 什么问题、为什么危险、建议怎么修
🟡 中风险：
- 文件:行号 — 什么问题、建议怎么修
🟢 低风险 / 建议：
- 文件:行号 — 小问题或改进建议

📌 结论：<可以放心 / 建议修复后再继续 / 必须修复>
```

### 7. 收尾
- 报告问题后**不要擅自改代码**：修复方案按严重程度列出 2~4 个选项（如适用），让用户拍板
- 修复若涉及账单数据操作，遵守项目数据安全规则（先备份、征得用户同意）
- 判断是误报的（测试假数据、示例配置）在报告里说明，不虚报也不放过
- 如产生了新的技术决策（新增工具、改变配置等），记入 CLAUDE.md 决策表（按项目规则）
