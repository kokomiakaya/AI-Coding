# 单元测试技能（Vitest）

给代码做「零件质检」：写测试 → 跑测试 → 交中文报告。

## 步骤

### 1. 确定测试目标
- 用户指定了文件/函数 → 测它
- 未指定 → 优先测纯逻辑（计算、规则、校验、数据映射等），其次才是界面组件
- 目标过宽时（如整个项目），拆成多个零件分次测，每次只测一个

### 2. 检查测试环境
- `package.json` 的 devDependencies 里没有 `vitest` → 执行 `npm install -D vitest`（国内网络慢时加 `--registry=https://registry.npmmirror.com`）
- 只有测 Vue 组件时才需要 `@vue/test-utils` 和 `happy-dom`，按需再装；纯逻辑测试不要装
- 本机从 VSCode 插件环境跑命令可能携带 `ELECTRON_RUN_AS_NODE`，若测试进程异常退出，命令前加 `env -u ELECTRON_RUN_AS_NODE`

### 3. 编写测试文件
- 位置：与被测文件同目录，命名为 `xxx.test.ts`
- 结构：`describe`（哪个零件）+ `it`（检查点，用中文写「应该……」）
- 只测对外可见的行为，不测内部实现细节
- 检查点要覆盖：正常情况 + 边界情况（空值、零、最大/最小值、非法输入）
- 测试文件是项目的一部分，随 git 一起存档
- 若逻辑写在 .vue 组件内部无法直接测：把纯逻辑抽到独立 .ts 文件再测。抽取 = 代码结构调整，必须先征得用户同意

### 4. 执行测试
- 一次性跑完：`npx vitest run`（不要用 watch 监听模式）
- 不通过时：判断是代码 bug 还是测试写错 → 修复后重跑，直到全部通过；修不好要如实说明
- 修复若涉及账单数据操作，遵守项目数据安全规则（先备份、征得用户同意）

### 5. 生成中文测试报告
用以下格式向用户汇报（这是给用户的报告，不是开发者的原始输出）：

```
🧪 单元测试报告

📋 测试对象：<文件/零件名>
✅ 通过：N 项
❌ 失败：N 项
（⏭️ 跳过：N 项，如有）

<逐条列出测了什么，一句话一条，用大白话>
- 「……应该……」✅

<如有失败：>
⚠️ 失败详情：
- xxx.test.ts:12「……」— 用大白话解释失败原因（预期什么、实际是什么）

📌 结论：<全部通过 / 已修复后通过 / 仍有 N 项未解决及原因>
```

### 5.5 写质检标记（供提交闸门检查）
测试全部跑完后（无论通过与否），写标记文件 `.claude/checks/unit-test.txt`，格式：

- 第 1 行：全部通过写 `PASS`；有失败写 `FAIL 原因：<一句话说明失败情况>`
- 第 2 行：改动指纹 —— 执行 `node .claude/scripts/commit-gate.mjs fingerprint`，把输出的编号原样抄下
- 第 3 行：当前时间（YYYY-MM-DD HH:MM）
- 之后：一句话摘要（✅ 通过 N 项 / ❌ 失败 N 项及关键原因）

例如：

```
PASS
e3b0c44298fc1c149afbf4c8996fb92427ae41e4
2026-09-29 14:30
✅ 单元测试全部通过（12 项）
```

写标记是收尾动作、不改变代码；标记文件已被 .gitignore 排除，不进版本库。

### 6. 收尾
- 全部通过后提醒用户：需要存档时说「提交」（gitcommit-agent 会走提交闸门流程）
- 如产生了新的技术决策（新增工具、调整结构等），记入 CLAUDE.md 决策表（按项目规则）
